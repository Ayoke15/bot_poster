# Подключение браузерной сессии VK

Этот способ позволяет боту обращаться к веб-методам сайта VK от имени редактора/администратора сообщества. Регистрировать собственное приложение VK или передавать ИНН не требуется. Протокол основан на описании [VKBrowserClient, версия ae3494a](https://github.com/t3chn0pr13st/VKBrowserClient/tree/ae3494a4131ca6bb6f742a26fdcfa04471b6646b); в проекте написана собственная реализация на Go. Это неофициальный интерфейс сайта; его доступность и срок жизни сессии определяет VK. Поддержка видео в этой версии не добавлена.

Пароль и код входа вводятся только на странице VK в отдельном локальном Chrome/Chromium. Утилита читает cookies после завершения входа; пароль не экспортирует и не сохраняет в PostgreSQL. На сервер переносятся зашифрованные cookies и веб-токен. Сессия даёт доступ к аккаунту, поэтому защищайте её как пароль: не отправляйте файл/ключ в чат, Git, PR или GitHub Actions. Шифрование защищает копию БД без ключа, но не защищает от захвата работающего сервера, где сессия расшифровывается для запросов. Закрытие окна входа завершает локальный браузер, но не отзывает сессию VK.

## 1. Создать зашифрованный файл на своём компьютере

Нужны Chrome/Chromium с графическим интерфейсом и Go 1.26+. Откройте каталог репозитория на ветке `feat/telegram-photo-posts` и соберите утилиту:

```sh
go build -o bin/vk-session ./cmd/vk-session
```

Для Windows используйте `go build -o bin/vk-session.exe ./cmd/vk-session` и запускайте `./bin/vk-session.exe`.

В окружении терминала задайте **существующий** `TOKEN_ENCRYPTION_KEY` вашего бота. Не генерируйте другой ключ для уже работающего сервера: старые реквизиты перестанут расшифровываться. Утилита сама не читает `.env`. Для Bash можно ввести ключ скрыто без сохранения значения в истории:

```sh
read -r -s -p 'TOKEN_ENCRYPTION_KEY: ' TOKEN_ENCRYPTION_KEY
export TOKEN_ENCRYPTION_KEY
```

Для PowerShell:

```powershell
$secureKey = Read-Host 'TOKEN_ENCRYPTION_KEY' -AsSecureString
$env:TOKEN_ENCRYPTION_KEY = [System.Net.NetworkCredential]::new('', $secureKey).Password
```

Получите ключ из собственной конфигурации сервера безопасным способом; файл сессии и ключ храните отдельно. Теперь запустите, заменив `123456789` своим Telegram ID:

```sh
./bin/vk-session login --owner 123456789 --group 242994137 --file session.vkenc
```

Откроется отдельное окно Chrome. Войдите в аккаунт VK, который администрирует тестовое сообщество. После завершения входа нажмите Enter в терминале. Утилита проверит роль, возможность публикации на стене и доступ к серверу загрузки фото, не создавая пост. При успехе создаст `session.vkenc`, привязанный к этому Telegram ID и сообществу. Существующий файл не перезаписывается — при повторном входе выберите новое имя. На Unix права файла — `0600`; на Windows ограничьте доступ к каталогу своей учётной записью.

## 2. Импортировать на сервер

Перенесите **зашифрованный** файл по SSH/SCP на свой сервер. Приложению нужны те же `TOKEN_ENCRYPTION_KEY` и Telegram ID, с которыми создан файл.

При Docker Compose в каталоге проекта:

```sh
docker compose build app
docker compose stop app
```

Файл должен читаться пользователем `65532` внутри контейнера. Для Linux можно подготовить отдельный закрытый каталог:

```sh
sudo install -d -o 65532 -g 65532 -m 700 /var/lib/bot-poster-import
sudo install -o 65532 -g 65532 -m 600 session.vkenc /var/lib/bot-poster-import/session.vkenc
docker compose run --rm --no-deps \
  -v /var/lib/bot-poster-import/session.vkenc:/run/session.vkenc:ro \
  --entrypoint /app/vk-session app import \
  --owner 123456789 --group 242994137 --file /run/session.vkenc
docker compose up -d app
```

PostgreSQL должен продолжать работать. Compose передаст ключ и адрес БД из `.env`; браузер/Chrome на сервере для импорта и публикаций не нужен. Если импорт не удался, причину утилита выведет без секретов; прежние реквизиты сохранятся. Запустите приложение обратно, даже если импорт не прошёл. Для сервера без Docker: остановите бот, экспортируйте `DATABASE_URL` и `TOKEN_ENCRYPTION_KEY`, выполните ту же команду `vk-session import`, затем запустите бот.

Импорт использует UPSERT по Telegram ID, сохраняет привязки каналов, состояние `/enable` и ожидающие задания текущего сообщества. Старый кеш вложений очищается; уже известные ID VK-постов сохраняются. Импорт в другую группу отклоняется: сначала явно отключите старую через `/clear_vk` (это отменит ожидающие задания). Работающий воркер блокирует импорт, поэтому требуется его остановить.

После успешного импорта удалите переносные копии файла, если не нужны для локального теста. При первом подключении напишите боту `/start`, `/connect_channel -100…`, `/enable`. При обновлении сессии используйте `/status`; повторно отправлять API-ключ через `/set_vk` не нужно — это заменит браузерную сессию.

## 3. Проверить публикацию

Разместите одну фотографию с подписью в подключённом Telegram-канале. Бот должен создать пост в VK и проверить, что загруженная фотография присутствует. Пост останется на стене. При ошибке проверьте `/status` и уведомление; успешный `wall.post` без ожидаемого вложения больше не считается доставкой.

Короткоживущие токены обновляются автоматически. Когда VK потребует повторный вход, бот приостановит очередь владельца и уведомит его. Повторите `login` и `import` для той же группы, чтобы продолжить. Не используйте `/disable` для временной паузы перед импортом: эта команда отменяет задания. Завершённые/окончательно неуспешные задания автоматически не публикуются заново.

Чтобы отключить доступ, выполните `/clear_vk` и завершите соответствующую сессию в настройках безопасности аккаунта VK. Команда удаляет реквизиты из текущей БД, но не отзывает сессию на стороне VK и не удаляет старые резервные копии.

## Живой тест фото

Запускайте на своём компьютере с файлом из шага 1, до удаления переносной копии. Нужны отдельные тестовые бот/канал/сообщество и PostgreSQL с правами CREATE SCHEMA. Тест создаёт настоящие посты в Telegram и VK и **не удаляет их**.

Переменные окружения:

- `TG_TEST_BOT_TOKEN` — тестовый бот без webhook, администратор канала с правом публикации.
- `TG_TEST_CHANNEL_ID`, `TG_TEST_OWNER_ID`, `VK_TEST_GROUP_ID` — тестовые ID; владелец должен быть администратором канала. Владелец и группа должны совпадать с файлом.
- `VK_TEST_WEB_SESSION_FILE` — путь к `session.vkenc`.
- `TOKEN_ENCRYPTION_KEY` — ключ, которым зашифрован файл.
- `TEST_DATABASE_URL` — отдельная тестовая PostgreSQL; временная схема удаляется после теста.
- `RUN_LIVE_INTEGRATION=true`.

`VK_TEST_COMMUNITY_TOKEN`/`VK_TEST_USER_TOKEN` для этого теста не нужны.

```sh
go test -race -tags=live -run '^TestLiveTelegramPhotoToVK$' -count=1 -timeout=7m -v ./internal/poster
```

Тест отправляет фото через `sendPhoto`, подаёт полученное сообщение локальному обработчику и запускает настоящий воркер. Проверяется наличие загруженного фото в VK; текст подписи не сравнивается, входящее событие Telegram не ожидается. До собственного успешного запуска этого теста живую работу браузерного способа считать подтверждённой нельзя. Обычный CI проверяет очередь/шифрование/протокол на заглушках и выполняет живой текстовый тест с ключом сообщества; фото без локального файла помечается SKIP.
